## 10B · Private guest lifecycle

| Policy | Local implementation |
| --- | --- |
| Identity | An explicit POST creates a new owner UUID and a signed guest bearer credential. The browser holds the guest token and selection in tab session storage. The same tab can reload. Account credentials keep their existing storage and login flow. Guest credentials cannot enter password sign-in or reuse an account owner. |
| Expiry | 60 minutes from creation using `GUEST_SESSION_MINUTES`. Requests check the durable lease and guest responses use `no-store`. The browser shows the deadline and clears their workspace when it ends. |
| Upload | CSV and TSV over multipart. Up to 3 saved datasets, 2 MiB per file, 10,000 rows and 16 columns. URL import, Excel, unregistered-file recovery and stored account sample copies require an account. Public sample exercises remain available. The backend checks both the request and the file. |
| Compute | 30 admitted processing attempts per lease. Upload, reparse, profile rerun, analysis, report generation and rendering or regenerating exports count against it. One queued or running background job per guest. Existing execution time limits apply. Stored metadata and finished report downloads remain accessible until the lease ends. |
| Caches | Guest computations bypass the process-wide frame and result caches. Signed-in cache reuse is keyed by dataset instance as well as file fingerprint and plan, including for two owners with identical uploads. |
| Clear and restart | Clear commits revocation before file deletion, and the same credential can repeat the clear safely. Owner rows and dependent dataset, session, result, report and job rows are reclaimed along with the owner's upload and report folders. A 30-second sweep and startup retry deferred cleanup. Startup also removes partial files and marks interrupted guest jobs failed so the reader can rerun them. |
| Work in progress | Workers check the lease before accepting or publishing work. A running CPU thread can finish its computation after revocation. Its result or report is discarded. Guest report downloads read the file before applying the final delivery check. |
| Logging and conversion | Guest lifecycle logs use event outcomes without filenames, dataset values, tokens, report content or owner identifiers. The loopback guest API used `--no-access-log`. Guest datasets have no conversion or transfer path to an account. Signing in separately creates an independent account workspace. |

Creation defaults to disabled. Local browser settings enabled `ALLOW_GUEST_SESSIONS=true` with the policy above, a single Uvicorn worker, disposable SQLite and local storage, and the mock provider. Guest API and UI paths block provider features. Migration `0002` adds the lease table so cleanup and quota accounting survive restarts. SQLite development startup also creates missing tables. PostgreSQL installations use Alembic before starting the new application.
