## 3. Code findings and deployment diagnosis

### 3.1 Why the Overview can load its shell and no analysis

1. `APP/backend/app/api/v1/router.py` registers `/api/v1/road-safety/overview` separately from `/frequency` and `/interventions`. `endpoints/overview.py:95` reads `ROAD_SAFETY_RELEASE_ROOT` (default `data/exports/road_safety`) and `ROAD_SAFETY_APPROVALS` on each request. The manifest lives at `<root>/descriptive_release/manifest.json`. The verifier requires an external named, dated `APPROVED` entry bound to the exact manifest SHA-256. It checks allowlisted outputs and digests. The route pins bundle `v3-d7-2`, schema 1, GEOID 42003, years 2004–2024, historical aggregate claim class and zero primary assignments. The artifact reader checks bytes again. The unavailable response is HTTP 503 with `detail.code=OVERVIEW_UNAVAILABLE`, null `data` and null `approval_state`. Pending, missing, invalid and changed bytes share this public response. The server logs carry the diagnostic reason. [Overview implementation](https://github.com/ExploratoryDataAnalysis/EDAgent/blob/87a7aea/EDAgent_Completed_Extension/EDAgent/backend/app/api/v1/endpoints/overview.py)
2. Standard `APP/docker-compose.yml` exposes 5173, 8000 and 5432, bind-mounts the code, and sets a browser API base of `http://localhost:8000/api/v1`. It supplies neither release variable nor ledger. An ordinary base-only launch therefore reaches the missing-ledger path if the request reaches the current backend. The URL targets the visitor's machine in a remote browser. Hard-coded local DB connection and default secret belong to dev. The backend image build excludes exports, uploads, test fixtures and `.env`. Packaging the image alone cannot provision D7. [Compose defaults](https://github.com/ExploratoryDataAnalysis/EDAgent/blob/87a7aea/EDAgent_Completed_Extension/EDAgent/docker-compose.yml)
3. `APP/docker-compose.staging.yml` overlays production settings and named volumes, mounts a dedicated bundle root and external ledger read-only, and removes direct postgres/backend port publication. The frontend listens on host loopback, builds with `VITE_API_BASE_URL=/api/v1` and uses the Vite proxy target `http://backend:8000`. The backend entrypoint runs `alembic upgrade head` before serving. The staging frontend uses Vite Preview. A public release needs an HTTPS ingress/static build, SPA fallback for document routes and an explicit `/api/v1` reverse proxy ahead of that fallback. Prevent ingress, browser service workers and CDN rules from caching protected release payloads against a revocable approval. Keep long-lived caching for hashed app assets only. [Staging Compose](https://github.com/ExploratoryDataAnalysis/EDAgent/blob/87a7aea/EDAgent_Completed_Extension/EDAgent/docker-compose.staging.yml) · [Phase 6 runbook](https://github.com/ExploratoryDataAnalysis/EDAgent/blob/87a7aea/docs/phase6_handoff.md)
4. `frontend/src/services/roadSafetyService.ts` waits for provenance plus five tables in one `Promise.all`. It strips table responses to `rows`, discarding structured metadata, and uses a shared Axios client with a 120-second timeout, bearer attachment and global 401 handling. A single table failure collapses all data. It also makes six independent reads while approval and files are checked per read. The frontend does not compare manifest identity across panel data. Start the page with the provenance decision, validate each table envelope and its bundle identity, and load independent panels with per-panel status and cancellation. If the gate becomes unavailable, clear protected content for the active release. A single network or parse failure may show a bounded panel error while same-release verified panels remain visible. Keep the no-data shell outside this decision. Give safe public messages for offline, retryable transport failure and reviewed data unavailable. Avoid interpreting the last one as confirmed pending approval.
5. `RoadSafetyPage.tsx:31` uses `staticPlot: true` and no mode bar. It plots trends and coverage but relies on tables for parts of severity composition. Its map is `county_grid.svg` in an image with a CSV link. The three D7 tables unused as interactive data are `source_missingness`, `historical_grid` and `severity_associations`. The accessible tables, existing captions, reproducible downloads and explicit null handling are good foundations. Use populated response values, computed denominators and caveat identifiers in figures and export metadata. [Current Overview UI](https://github.com/ExploratoryDataAnalysis/EDAgent/blob/87a7aea/EDAgent_Completed_Extension/EDAgent/frontend/src/pages/RoadSafetyPage.tsx)
6. `App.tsx` places `/` and all analyser routes behind `Gate`; `/road-safety` and `/illustrative-scenario` are public. `Sidebar.tsx` hides labels below its initial 900 px threshold, shows three guest entries and hardcodes the version. `AppLayout.tsx` couples public reading to a full-viewport app shell with inner scrolling. `HomePage.tsx` is a signed-in upload-centric product page. Split reading and analysis layouts, support browser back/focus and plain deep links, and keep explicit text labels on phone. [Router](https://github.com/ExploratoryDataAnalysis/EDAgent/blob/87a7aea/EDAgent_Completed_Extension/EDAgent/frontend/src/App.tsx)
7. `.github/workflows/edagent-ci.yml` installs Python dependencies and runs `backend/tests`, then runs a separate frontend build. It has no declared image promotion, external deploy job or browser smoke invocation. Treat handoff screenshots and local fixture passes as evidence for those environments. Require version identification, reverse-proxy health and documented rollback at promotion. ### 4.1 Boundaries that apply across product surfaces

- `PRIMARY_SITE_ASSIGNMENTS_ACCEPTED=0`. County/grid historical concentration has no aligned travel-exposure denominator. Valid road-site counts would require accepted attribution, an independently eligible and zero-inclusive observation frame and reporting completeness. Frequency would also require time-, direction- and site-compatible exposure. EB would require a defensible calibrated SPF. Current Phase 3 evidence and Phase 4 no-go are sufficient to close those v3 work items.
- Station 375's 2023 observed count is `UNKNOWN`. The archived 11,072 vehicles/day applies to the traffic section containing segment 0080 under the recorded restrictions. It does not establish a directional site-year offset, an expected count or a treatment baseline. Public interfaces should present the generic limitation. Keep station details in the audit record.
- V3 D6 is `OUT_OF_SCOPE_NO_GO`; D12–D15 (live safety feed, short-horizon forecast, route comparison and replay) are outside release. Do not turn those into checklist dependencies for D7–D11.
- Preserve v3's Overview-first sequencing and its existing authenticated analyser contract through Phase 7. Guest access is a product extension with its own owner and abuse tests. It can reuse the engine without reducing existing session/history/report capability.
- Treat public `UNKNOWN` and `UNAVAILABLE` as typed reasons. Render gaps in lines and unavailable states in accessible tables. A value of zero is measured under a defined rule. A zero denominator produces a null ratio. A numeric code with semantic “unknown” can be present in the source.
- Findings suitable for narrative include the 2016 break, 2024 recording limits, conditional association magnitude, county mapping coverage and the boundary on model claims. Weather and road-surface changes around 2018–2019 require provenance review. Count, coverage and code shifts offer different evidence.

**Two-minute visitor.** Land on a county-specific question and a single annotated chart with a plain-language takeaway. Scroll through the 2016 comparability cue, mapping coverage and a scoped explanation of outcomes. Discover one route to explore and one link to reproduce. On mobile use horizontally compact controls and stacked content. A reader can complete the summary without opening a menu.

**Analyst with 20–30 minutes.** Open the record directly, select a year, inspect numerator and denominator, follow the coding-break and pooling notes, compare retrospective validation evidence, and download the exact reviewed table. A citation link carries the claim ID, table row key or filter, release identity and period. A stable URL supports copy/paste and back navigation. Download metadata keeps both the original source and the transformed table identity.

**Planner or researcher.** Inspect the county grid and its coverage, open a cell, see what a count says, then read why site attribution and exposure are insufficient. Move to a worked hypothetical scenario with values clearly labeled as invented. Return to the source of the treatment evidence independently.

**General analyser guest.** Start with the county annual aggregates, compare a total or trend, then optionally upload an unrelated file, profile it, run a manual analysis, export, and clear the session. Sign-in appears only for account-level persistence or features deliberately confined to accounts. AI is optional inside the workspace and has a deterministic fallback path.


## 6. Evidence pipeline and web contract

```text
Frozen notebook + source/run manifest
        │ offline build and reconciliation
        ▼
Versioned derivative ─── independent review decision for exact bytes
        │ approved manifest + payload checks
        ▼
Typed public API ─── presentation metadata and row/metric identity
        │
        ├── React figure, table and text sharing one filter state
        ├── checked CSV / GeoJSON downloads
        └── analyser sample derived from approved aggregate columns
```

### 6.1 Build and promote

1. Keep `analysis/EDA_v6.ipynb`, `analysis/outputs/run_manifest.json` and frozen outputs unchanged. Record dataset resource, source and notebook hashes, package versions, derivation Git revision, run ID, geometry vintage, deterministic ordering and numeric tolerance. Use `analysis/run_v6_repro.py` for isolated reproduction. Distinguish byte checks from numerical reconciliation.
2. Reuse `scripts/build_descriptive_release.py` and the existing D7 contract first. Author separate offline extracts for new groups of claims. Record exact artifact inventory and artifact-level checksums. If useful content exists only in stored notebook outputs, first reproduce its derivation into reviewable tables and compare to the frozen evidence. HTML screenshots, matplotlib images and pickled models provide no interactive data contract.
3. Use typed JSON for browser-facing tables, streaming/downloadable CSV for clean tabular interoperability, GeoJSON for known boundary or reviewed cells and lightweight SVG/PNG for fallbacks and citation images. For a larger reviewed aggregate, use compressed JSON transport first. An offline/internal Parquet copy may help reproducibility if volume warrants it. Keep binary model objects and full prediction rows out of public bundles. Avoid storing Plotly figure specs as the scientific source of truth. Version figure recipes and use them to reconstruct plots over vetted data.
4. Keep approval and run provenance independent. Publish one coherent bundle version per page and include its manifest ID in cache keys and exports. Handle pre-rendering as an application shell with static trackable methods content. Approved numbers load from the live gate. Prove revocation and rollback behavior across browser routes, downloads, service worker, HTTP cache and analyser sample. A hash match with pending decision stays unavailable. An older approved bundle requires a compatible pin and explicit decision for its bytes.
5. Avoid a user-triggered notebook execution path. “Live” can mean filters, linked selections, offline-generated curves, a deterministic client-side lesson or computation over a user's own active session. The corresponding UI labels should identify the computation and data scope.

### 6.2 Preserve the features of the existing API envelope

For every dataset fed to a figure preserve `table_id`, `schema_version`, `row_key`, period and grain, geography and GEOID, population, `units`, `ratios`, `annotations`, caveat codes/text, source hashes, `run_id` and `bundle` metadata. Derive presentation IDs from the stable row key and metric column. The row-index annotation is meaningful only with the exact row order in the response. Associate annotations before filter/sort. The metric endpoint is useful as a link and spot check. Avoid one network request per chart point.

**Proposed figure descriptor**, a frontend recipe keyed by release data. D7's wire schema can stay at 1 for Phase 1.

| Field | Example content and validation |
| --- | --- |
| `id`, `sourceTable`, `metric`, `keyFields` | `annual-hour-coverage`, `field_coverage_by_year`, `covered_percent_of_reported`, period key + `metric_id=valid_hour`. Validate that the series has one row per expected year. |
| `basis`, `filters`, `aggregation` | County, all reports in that year, years supported by table, count-over-count. For rolled-up scopes, sum numerator and denominator only across disjoint periods and comparable populations. Avoid averaging percentages or combining annual, era and whole-county totals. |
| `axis`, `annotation`, `supportedControls` | Percent (0–100), 2024 missingness marker, select year. Display numerator, denominator, inclusive period, unit and coverage. Keep `UNKNOWN`, `UNAVAILABLE`, underflow and measured zero distinct. |
| `caption`, `methodAnchor`, `dataLink` | Conclusion scoped to the cohort, known limitation, durable source link. Expose table/download by keyboard and include matching filter provenance in any chart export. |

Add schema validation at the release boundary and typed mapping in the frontend. Tie every numerical claim to a reviewer-approved ID, its formula or row and a bundle version. A single reviewed bundle can also deliver a compact bootstrap index of which charts have available approved data.
